# P4 plan: desktop app pages

Branch `p4-desktop-pages`, made from `main` at `8f2b8e8` (foundation and stage B are both in it).
I only touch P4 paths: `desktop/src/pages/` (not `factory-floor/` or `agent-map/`), `desktop/src/global/`,
`desktop/src/components/`, `desktop/tests/pages/`, `docs/desktop-pages.md`, `docs/requests/p4.md`, and this file.

## How it fits the foundation

- Each page is `pages/<name>/route.tsx`, which default-exports a `PageRoute`. The pages are found
  automatically, so no shared file changes.
- Data comes through `apiFetch` and TanStack Query, and live updates through `useLiveEvents`. Types
  come from `src/api/types.ts`; they already cover every endpoint I need, so I make no request to P1.
- Each page has a `mocks.ts` that calls `registerMock`. Mock data lives in one shared file,
  `components/mock-data.ts`: 8 machines, 10 customers, and orders in every state. The app then
  works fully with `VITE_USE_MOCKS=true`.
- No new packages. Charts use Recharts (already installed). The Gantt is a small piece built by
  hand with CSS. The PDF viewer is an `<iframe>`, so it uses Chromium's built-in viewer.
- The `data-testid`s and route paths in CONTRACT item 12 are used exactly as listed.

## Pages and roles

| Page | Path | Sidebar order | Roles (admin always) |
|---|---|---|---|
| Login | `/login` (public) | none | everyone |
| Approvals inbox + approval pack | `/approvals`, `/approvals/:approvalId` | 20 | manager |
| Orders + detail + field check + upload | `/orders`, `/orders/:orderId` | 30 | manager, sales, planner |
| Schedule (Gantt, read-only) | `/schedule` | 40 | manager, planner |
| Materials + detail, movements, holds, shortages, cycle count | `/materials`, `/materials/:materialId` | 50 | manager, planner (read), store |
| Quotations + "Can we make this date?" | `/quotations` | 60 | manager, sales |
| Dashboards | `/dashboards` | 70 | manager, planner |
| Quality | `/quality` | 90 | manager, qc |
| History (audit search, diff, CSV) | `/history` | 100 | manager |
| Settings (users, machines, shifts, holidays, thresholds, demo reset) | `/settings` | 110 | admin |

The store role never sees prices: `Money` renders nothing for that role, and price columns are left out.

## Build order (one commit each)

1. Components and shared mock data.
2. Login, Orders (list, detail, timeline, field check, upload, mark as sent).
3. Approvals (inbox and approval pack with option cards, MiniGantt, reject dialog, Ask orchestrator).
4. Materials, Quotations, Schedule.
5. Dashboards, Quality, History, Settings.
6. Global chat, notifications and live refresh; then tests, docs, and the ownership check.

## Tests (`desktop/tests/pages/`, Vitest with mocks)

The approval pack renders every section. Reject needs a reason. Field check lets you edit only
flagged fields. The store role sees no prices. Materials form validation. Chat streams its replies.
A notification event shows a toast. Live refresh invalidates the right queries. Each role sees only
its own sidebar pages.
