# P2 domain agents plan

Implement the Order, Material, and Planning agents and their REST endpoints on `p2-domain-agents`. The branch starts from `main` at `83ed937`, which contains P1's foundation and the current shared contract.

## Scope

Use the existing SQLAlchemy models, Pydantic contracts, messaging helpers, Claude client, and test fixtures. Keep changes within the P2 paths in `ownership.json` and record shared integration gaps in `docs/requests/p2.md`. Use `effective_settings` for runtime business thresholds and store timestamps in UTC, with business dates interpreted in `APP_TIMEZONE`.

## Implementation sequence

- [ ] Build the Order worker and a shared intake service for IMAP and uploads. Validate and store each supported attachment, create its source document and order, audit intake, and publish `event.order.received` after commit. Deduplicate by Message-ID and make retries safe when storage, publication, or mailbox acknowledgement fails.
- [ ] Extract PDF and image content with Claude and convert Word and Excel attachments to text. Use the foundation's `response_schema` support to capture field values, confidence, and source text. Match customer and part codes deterministically, compare with open quotations, persist the fields and lines, and emit the revised-PO event for a matching confirmed order. Build customer reply drafts from the selected option's database facts and audit order closure.
- [ ] Implement Material actions from the movement ledger and BOM, including scrap, live hold balances, supplier lead times, stock warnings, temporary expiry, firm confirmation, release, and purchase requests. Lock material rows in a stable order for hold and inventory writes, and verify retries and simultaneous reservations for the same stock.
- [ ] Implement the Planning worker with a single consumer and `prefetch=1`. Build a bounded CP-SAT model for routing precedence, machine calendars, downtime, locked work, and material readiness. Generate as-requested, delay, split, overtime, and move-other-order options where feasible. Calculate delivery dates, costs, load, margin, and recommendations in code. Give Claude the computed facts for explanations and provide a deterministic fallback when explanations are unavailable.
- [ ] Persist options and their tentative slots together. Recheck selected slots against current capacity before locking, update displaced orders atomically, and support release and machine replan. Reuse the material and solver calculations in the read-only what-if path.
- [ ] Implement the P2 endpoints in `orders.py`, `materials.py`, `quotations.py`, and `planning.py` with the foundation's REST schemas. Apply sales and store permissions, hide pricing from store responses, audit writes, and support the `page_size=200` order-list request used by the end-to-end tests.
- [ ] Add ten PO fixtures with mocked Claude responses and test the worker and API entry points. Cover low-confidence and unmatched fields, quote mismatches, revisions, duplicate intake and task delivery, concurrent reservations, hold expiry, solver options and time limits, calendars, stale slots, read-only what-if requests, and role restrictions. Gate the optional live Claude test behind `RUN_LIVE_LLM_TESTS=1`.
- [ ] Run the domain suite against PostgreSQL, lint the P2 Python files, and verify service and router discovery. Write `docs/domain-agents.md`, run `scripts/check-ownership.sh p2`, then commit and push the branch for P1's handoff.

## Cases to resolve during implementation

- Check ambiguous master-data matches and unavailable supplier lead times against the shared payloads. Surface them for review or through warnings using the existing schema.
- Distinguish a solver time limit from proved infeasibility. Preserve feasible results and explain omitted options from the solver outcome.
- Validate that a price restriction also covers extracted fields, source documents, option margins, and quotation responses.
