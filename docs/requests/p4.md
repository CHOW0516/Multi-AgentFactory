# P4 requests and assumptions

Things P4's pages rely on that the contract does not pin down. P1 checks these at merge time.

## For P1
1. **Done:** mock mode crashed whenever any `mocks.ts` existed. Fixed in PR #2 (`p1-fix-mock-loading`): `mocks.ts` now loads lazily.
2. **Done (connect-everything):** **Demo reset endpoint:** Settings → Demo calls `POST /api/demo/reset` (admin only, only when `APP_MODE=demo`). It should run the same code as `python -m app.simulator reset`. It is not in the contract yet.

## For P2
3. **`GET /orders` filters:** `status`, `customer_id`, `due_to` (date, inclusive), `late_risk=true`, `page_size` (up to 200), `page`.
4. **`PATCH /orders/{id}/fields` body:** a JSON array of `FieldCorrection` (`[{field_id, corrected_value}]`). The page sends PATCH only when something changed, then always sends `POST /orders/{id}/fields/confirm`.
5. **`POST /orders/upload`:** multipart form with the file in the field `file`. It returns the new `OrderSummary`, and the page opens that order.
6. **`GET /orders/{id}/plan-options` and `GET /orders/{id}/customer-message`:** return 404 when there is nothing yet. The page shows "No plan yet" or "No reply drafted yet".
7. **Plan option `status`:** the order page shows the option whose status is `chosen` or `locked`, or else the recommended one.
8. **`GET /stock-movements?material_id=`** filters by material, newest first.
9. **List endpoints:** they can return either a plain array or `Page<T>`. The pages accept both.

## For P3
10. **Dashboard chart names** for `GET /dashboard/charts/{name}?from&to`: `on_time_delivery`, `po_to_approval_hours`, `machine_utilisation`, `extraction_accuracy`, `planned_vs_actual` (series "Planned" and "Actual"), `llm_cost_daily`, `failed_workflows`. If a name is unknown, return 404; the card shows "No data". `GET /dashboard/kpis?from&to` returns `KpiTile[]`, and the tiles show whatever it returns.
11. **Chat stream:** `POST /chat` returns plain text chunks (for example `text/plain` with chunked transfer). A line that starts with `[tool] ` names a tool the orchestrator used; the panel shows it as a chip.
12. **`GET /qc/orders/{id}`** returns `{plan: QcPlanOut | null, records: QcRecordOut[]}`, or 404 when there is no plan.
13. **`GET /history`** filters: `actor` (user name or agent), `entity`, `from`, `to`, `q` (free text), `page`, `page_size` (50). `GET /history/export.csv` takes the same filters and accepts `?token=`.
14. **Approvals:** "Approve option" sends `{decision: "approve", chosen_option_id}`. Reject sends `{decision: "reject", reject_reason, comment}`.
15. **Notifications:** a live `notification` event with an empty `user_ids` means it is for everyone.
