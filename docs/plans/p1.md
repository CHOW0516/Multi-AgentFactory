## Decisions

- Python 3.12 (in Docker and for local tests). Library versions are pinned to current stable releases.
- PO intake in dev uses **GreenMail** (SMTP + IMAP).
- The Anatomy kit is copied from the Anatomy skill into `desktop/src/iso/` without changes.
- Money is stored as `Numeric(14, 2)`, times as UTC `timestamptz`.
- Passwords: bcrypt. JWT: HS256 with `JWT_SECRET`.

## Testing setup

- Docker runs in the build environment, so I test with the real `docker compose up` (PostgreSQL, RabbitMQ, GreenMail, API).
- Messaging tests run against a real RabbitMQ. Unit tests can also use an in-memory fake broker for speed.
- Desktop: type check, unit tests and `vite build` run here. The Electron window itself is opened on your machine.

## Done when
Migrations apply, seed runs, `/api/health` and login work, backend foundation tests pass, desktop type check, tests and build pass, `scripts/check-ownership.sh p1` passes. Then I merge into `main` and P2 to P5 can start.

## Edge cases covered by tests
Missing required env key stops start-up; same message delivered twice runs the handler once; failing handler retries then dead-letters; LLM daily cost limit blocks non-critical calls; wrong role gets 403; router auto-discovery picks up a new file; ownership script catches a file outside the allowed paths.

## Stage B edge cases and tests

- Demo PO: every layout renders a valid PDF; each of the 4 mistakes changes only its field; no mistake keeps quotation values; a PO uses an open quotation; with no open quotation it falls back to a customer part; an empty database sends nothing (`test_simulator.py`).
- Live email: a demo PO really arrives in the GreenMail inbox with a PDF attachment (skipped when GreenMail is not running).
- Machines: running + count while a locked slot is active; no repeat events when nothing changed; idle after the slot ends; breakdown publishes `down`, stays silent during repair, and goes back to `running` after repair.
- Backups (tested by hand): first dump at start, schedule fires on time, pruning keeps the newest `BACKUP_KEEP`, half-written dumps never look complete (`.partial`), restore without `--yes` changes nothing, restore stops and restarts only the app services that were running, and a failed restore rolls back (`--single-transaction`).
- E2E harness (tested by hand): Electron starts from `dist-electron/main.cjs`, logs in against the live API; the 4 flow tests run after the merge.
