# P5 integration requests

## P1 desktop mock registry

The eager mock glob in `desktop/src/api/client.ts` can evaluate a mock module before `mockRoutes` is initialized. P5 uses idempotent installers called by its route modules after the client loads. Please switch the shared loader to a lazy glob and await the imports if automatic registration is needed across pages.

## P3 machine and agent APIs

- Confirm the roles allowed to call both machine operations. The current controls are available to managers, planners and admins. The API remains the authority on write access.
- Confirm that `utilisation_today` and `success_rate_today` use a 0–1 fraction. P5 formats these fractions as percentages.
- The contract identifies material holds and confirmations but has no specific material issue event. The cart accepts a successful Material result with an explicit issue marker and a machine ID, or an order number with exactly one matching bay. Publish the target machine ID when available.
- A persistent daily agent failure total and an authoritative current-task list would let the map show historical failures and pending tasks from before the most recent 50 messages. The current indicator counts failures observed while the map is open and derives the visible task list from recent messages.

## Anatomy verification files

The vendored drawing kit omits the Anatomy CLI verification tools. P5 uses the installed skill’s checker where available and keeps a Playwright capture script in its own test folder. The drawings use planar solid geometry and SVG, including the rectangular cabling conduits, without WebGL or a runtime dependency on the installed skill.
